# 旅游景点地图导航系统 - 项目说明文档

## 1. 项目概述

### 1.1 项目背景

随着旅游业的快速发展，游客对旅游信息获取和导航服务的需求日益增长。传统的旅游指南和导航系统往往存在信息更新不及时、功能单一、用户体验不佳等问题。本项目旨在开发一个综合性的旅游景点地图导航系统，为游客提供便捷、准确、实时的旅游信息服务和导航功能，提升旅游体验。

### 1.2 项目目标

- 建立一个完整的旅游景点信息管理系统，包含景点详情、图片、评价等信息
- 实现基于地图的景点展示和导航功能，支持多地图服务提供商
- 提供景点搜索、筛选、收藏等个性化功能
- 支持旅游活动发布、报名和管理
- 构建用户评价和评分系统，促进用户互动
- 实现前后端分离的架构设计，确保系统的可扩展性和可维护性

### 1.3 项目特点

- **多地图服务支持**：通过适配器模式支持高德、百度、腾讯等多种地图服务
- **响应式设计**：支持不同设备的访问和操作
- **实时性**：提供实时的导航信息和位置服务
- **个性化**：根据用户偏好提供个性化的景点推荐和服务
- **社交互动**：支持用户评论、点赞、分享等社交功能
- **高可用性**：系统设计考虑了负载均衡和容错机制

### 2.3 关键设计模式

#### 2.3.1 适配器模式

**用途**：用于地图服务的统一接入和管理

**实现方式**：
- 定义`MapService`接口，规范地图服务的基本操作
- 为每个地图服务提供商实现对应的适配器类
- 通过工厂类创建和管理不同的地图服务实例

**优势**：
- 屏蔽了不同地图服务的实现差异
- 便于切换地图服务提供商
- 新增地图服务时，只需添加对应的适配器类，无需修改现有代码

#### 2.3.2 工厂模式

**用途**：创建地图服务实例、业务对象实例等

**实现方式**：
- `MapServiceFactory`：用于创建不同类型的地图服务实例
- `ServiceFactory`：用于创建业务服务实例

**优势**：
- 隐藏了对象创建的细节
- 集中管理对象的创建过程
- 便于扩展和维护

#### 2.3.3 观察者模式

**用途**：用于用户状态管理、数据变更通知等

**实现方式**：
- 定义观察者接口和被观察者接口
- 实现用户状态管理的观察者模式
- 实现数据变更的发布-订阅机制

**优势**：
- 解耦了观察者和被观察者
- 支持广播通信
- 便于系统扩展

### 3.1 数据库结构概述

系统使用MySQL作为关系型数据库，主要包含以下数据表：

- **用户相关**：`user`, `user_role`, `role`, `permission`
- **景点相关**：`spot`, `spot_category`, `category`, `spot_image`
- **活动相关**：`activity`, `activity_participant`
- **评论相关**：`review`, `review_image`, `review_like`

### 3.3 数据库索引设计

为了提高查询性能，系统在以下字段上建立了索引：

- `user(username)`：加速用户登录和查找
- `spot(name, city)`：加速景点名称和城市查询
- `spot(latitude, longitude)`：加速地理位置查询
- `activity(start_time, status)`：加速活动时间和状态查询
- `review(target_id, target_type)`：加速按目标查询评论
- `favorite(user_id)`：加速用户收藏查询
- `browse_history(user_id)`：加速浏览历史查询

### 3.4 数据备份策略

- **全量备份**：每日凌晨2点执行一次全量备份
- **增量备份**：每小时执行一次增量备份
- **备份保留**：全量备份保留30天，增量备份保留7天
- **异地备份**：备份数据自动上传至云存储，确保数据安全

## 4. API设计

### 4.1 API设计原则

- **RESTful风格**：遵循RESTful API设计规范
- **版本控制**：API路径中包含版本号，便于兼容升级

- **认证模块**：登录、注册、登出、Token刷新
- **用户模块**：用户信息管理、密码修改

## 9. 安全策略

### 9.1 数据安全

- **数据加密**：敏感数据（如密码）使用加密存储
- **传输加密**：使用HTTPS协议加密传输数据
- **数据备份**：定期备份数据，确保数据安全
- **访问控制**：严格的权限控制，确保只有授权用户才能访问数据

### 9.2 应用安全

- **输入验证**：对所有用户输入进行验证，防止注入攻击
- **XSS防护**：对输出进行转义，防止跨站脚本攻击
- **CSRF防护**：使用CSRF Token防止跨站请求伪造
- **SQL注入防护**：使用参数化查询，防止SQL注入
- **认证授权**：使用JWT进行认证，基于角色的授权控制

### 9.3 部署安全

- **服务器安全**：定期更新系统和软件补丁
- **防火墙配置**：配置防火墙规则，限制访问
- **日志监控**：记录系统日志，监控异常行为
- **入侵检测**：使用入侵检测系统，及时发现和处理安全问题
